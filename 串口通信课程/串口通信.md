## 1. 串口通讯协议简介

串口通讯（Serial Communication）是一种设备间非常常用的串行通讯方式，因为布线简单、协议轻量，绝大多数电子模块（GPS、蓝牙、WiFi、传感器、调试接口）都支持它。嵌入式工程师调试设备时，也几乎总是用串口输出调试信息。

和芯片分为内核层与片上外设一样，理解通讯协议最基本的方法是**分层**：把它分为**物理层**和**协议层**。

- **物理层**：规定通讯系统中机械、电子部分的特性，确保原始比特能在物理媒体上传输——相当于规定"用嘴巴还是用肢体交流"。
- **协议层**：规定通讯逻辑，统一收发双方的数据打包、解包标准——相当于规定"用中文还是英文交流"。

### 1.1 物理层

STM32 的 USART 引脚输出的是 **TTL 电平**信号。常见的串口物理标准对比如下：

**表 1-1 TTL 电平标准与 RS-232 电平标准**

| 通讯标准 | 电平标准（发送端） | 典型接口/器件 |
| --- | --- | --- |
| TTL | 逻辑 1：2.4V~3.3V；逻辑 0：0~0.5V | STM32 引脚直连、CH340/CP2102 USB 转串口 |
| RS-232 | 逻辑 1：-15V~-3V；逻辑 0：+3V~+15V | 老式 PC 的 DB9 COM 口 |

注意两点：

1. RS-232 的电平对逻辑 1/0 的定义与 TTL **相反且电压幅度大**，STM32 引脚绝对不能直接接 RS-232 电平，否则可能烧毁 IO。需要经过 **MAX3232** 之类的电平转换芯片互转。
2. 现代调试场景通常用 **USB 转 TTL 串口模块**（CH340、CP2102、FT232）直连 STM32 的 TX/RX 引脚，跳过 RS-232 层。

实际接线只需三根线：

**表 1-2 最小系统串口接线**

| 信号线 | 方向 | 说明 |
| --- | --- | --- |
| TX | 本机发出 | 接对方 RXD（**交叉相连**） |
| RX | 本机接收 | 接对方 TXD（**交叉相连**） |
| GND | — | **必须共地**，否则双方电平基准不一致，通讯不可靠 |

工程上常裁剪掉 RTS/CTS/DTR/DSR 等调制解调器控制线，只用 TX、RX、GND 三线直接传数据。

### 1.2 协议层

串口数据包由发送设备 TX 接口传到接收设备 RX 接口。协议层规定数据包内容由 **起始位 + 有效数据 + 校验位（可选）+ 停止位** 组成，通讯双方格式必须约定一致。我们平时说的 `115200 8-N-1`，就是"波特率 115200、8 位数据、无校验（None）、1 位停止位"的简写。

#### 1.2.1 波特率

异步通讯没有时钟线，双方必须约定每个码元的时长（即波特率）才能正确解码。F407 的 USART 使用**小数波特率发生器**，常用波特率有 9600、19200、115200 等。波特率越大，传输越快，但抗误差能力越差。

#### 1.2.2 起始位与停止位

- **起始位**：1 位逻辑 0（拉低一个位周期），空闲线路保持高电平。
- **停止位**：逻辑 1，可选 0.5、1、1.5、2 个位长；F407 的 HAL 库常用 `UART_STOPBITS_1` 和 `UART_STOPBITS_2`。

#### 1.2.3 有效数据

数据帧长度可配 8 位或 9 位（`UART_WORDLENGTH_8B` / `UART_WORDLENGTH_9B`），由低位移先发送。

#### 1.2.4 数据校验

可选的校验位用于检测传输中的干扰错误：

**表 1-3 校验方式**

| 校验方式 | HAL 宏 | 规则 |
| --- | --- | --- |
| 无校验 | `UART_PARITY_NONE` | 数据包不含校验位（最常用） |
| 奇校验 | `UART_PARITY_ODD` | 数据位+校验位中"1"的个数为奇数 |
| 偶校验 | `UART_PARITY_EVEN` | 数据位+校验位中"1"的个数为偶数 |

使能校验后，发送方硬件自动添加校验位，接收方自动检验；检验失败时 `USART_SR` 的 PE 位置 1。注意：使能奇偶校验时，字长一般配成 9 位（8 数据 + 1 校验）。

## 2. STM32F407VET6 的 USART 简介

STM32F407VET6 共有 **6 个串行通信外设**：USART1、USART2、USART3、USART6 为通用同步异步收发器，UART4、UART5 只有异步功能（USART 裁剪掉同步时钟输出即 UART）。我们平时说的"串口通信"基本都是 UART 异步模式。

USART 的主要特性：

- 满足工业标准 NRZ 异步串行数据格式，支持同步单向通信、半双工单线通信；
- 小数波特率发生器，波特率可灵活配置；
- 支持 RTS/CTS 硬件流控、DMA、IrDA、LIN、智能卡等扩展模式（VET6 常用不到）；
- 支持多种中断：发送完成 TC、发送寄存器空 TXE、接收非空 RXNE、空闲线路 IDLE、校验错误 PE、噪声/帧错误等。

F407VET6 各串口的时钟来源与引脚映射（CubeMX 选引脚时直接查这张表）：

**表 2-1 STM32F407VET6 USART 资源与引脚映射（LQFP100 可用引脚）**

| 外设 | 总线 | 时钟上限 | TX 引脚 | RX 引脚 | 复用 AF |
| --- | --- | --- | --- | --- | --- |
| USART1 | APB2 | 84MHz | PA9 / PB6 | PA10 / PB7 | AF7 |
| USART2 | APB1 | 42MHz | PA2 / PD1 | PA3 / PD5 | AF7 |
| USART3 | APB1 | 42MHz | PB10 / PC10 | PB11 / PC11 | AF7 |
| UART4 | APB1 | 42MHz | PA0 / PC10 | PA1 / PC11 | AF8 |
| UART5 | APB1 | 42MHz | PC12 | PD2 | AF8 |
| USART6 | APB2 | 84MHz | PC6 | PC7 | AF8 |

> 说明：PC10/PC11 同时是 USART3 和 UART4 的引脚，靠不同的 AF 编号区分，硬件设计时二选一。VET6 为 100 脚封装，没有 PG 端口，USART6 只能用 PC6/PC7 这组引脚。

STM32 的 USART 输出 TTL 电平，若需要对端是 RS-232 标准信号，需外加 MAX3232 转换。调试时最常见用法是把 USARTx 的 TX/RX 接到板载 USB 转串口芯片（如 CH340），在电脑串口调试助手上"打印"程序运行信息。

## 3. USART 内部结构详解

掌握功能框图（发送器/接收器/波特率发生器各模块）就掌握了 USART 的核心，编程思路会非常清晰。下面按模块拆解。

### 3.1 功能引脚

- **TX**：发送数据输出。
- **RX**：接收数据输入。
- **nRTS / nCTS**：硬件流控的请求发送/允许清除发送，低电平有效，仅全功能 USART 且开启流控时使用，CubeMX 默认 `Hardware Flow Control = None`。
- **SCLK**：同步模式时钟输出，仅 USART 同步模式使用，普通串口通信不涉及。

CubeMX 中 Mode 选项的 **Asynchronous** 就是最常用的异步模式，勾选后才会占用 TX/RX 引脚。

### 3.2 数据寄存器（DR）

`USART_DR` 只有低 9 位有效，实际包含两个寄存器：

- **TDR**（发送）：写 DR 即写入 TDR，硬件自动搬到发送移位寄存器逐位发出；
- **RDR**（接收）：读 DR 即读出 RDR，接收移位寄存器收满一帧后搬入。

发送流程：TE 置 1 → 先发一个空闲帧 → 写数据 → 移位输出（低位在前）→ 写完最后一个字节后**等待 SR 的 TC 位=1** 才算真正发完。HAL 库的 `HAL_UART_Transmit()` 内部已帮你处理 TXE/TC 判断。

接收流程：RE 置 1 → RX 线搜索起始位（特定序列 1110X0X0X0000）→ 按波特率采样 → 收满移入 RDR → RXNE 置 1 → 读 DR 取数据（读操作自动清 RXNE）。

发送/接收关键标志位小结：

**表 3-1 常用标志位**

| 名称 | 描述 |
| --- | --- |
| TE / RE | 发送使能 / 接收使能 |
| TXE | 发送数据寄存器空（逐字节写下一字节的条件） |
| TC | 发送移位寄存器也空了，整个发送完成（发完一批数据要等它） |
| RXNE | 接收数据寄存器非空（有数据可读） |
| ORE | 溢出错误：RXNE 还没读走新数据又来了 |
| IDLE | 空闲线路检测：一帧数据流结束后线路空闲了一个字符时间 |

### 3.3 小数波特率生成

波特率公式（16 倍过采样，`OverSampling = UART_OVERSAMPLING_16`）：

```
 baud = fPCLK / (16 × USARTDIV)
```

其中 `fPCLK` 为该 USART 所挂总线的时钟（F407 CubeMX 默认 168MHz 系统时钟下：APB2 = 84MHz，APB1 = 42MHz），`USARTDIV` 是写入 `USART_BRR` 的无符号定点数，高 12 位为整数部分 DIV_Mantissa，低 4 位为小数部分 DIV_Fraction（权值 1/16）。

**手算示例**：USART1（fPCLK = 84MHz）、16 倍过采样、目标 115200：

```
USARTDIV = 84 000 000 / (16 × 115 200) = 45.5725
DIV_Fraction = round(0.5725 × 16) = 9  → 0x9
DIV_Mantissa = 45 → 0x2D
BRR = 0x2D9
```

回算实际波特率：84 000 000 / (16 × 45.5625) ≈ **115226**，与目标误差 0.02%，在通信允许范围内。

> 这些取舍计算 CubeMX 生成代码时由 HAL 库自动完成，理解原理主要用于排查波特率偏差和手册阅读。8 倍过采样（`UART_OVERSAMPLING_8`）原理相同，权值由 16 改为 8，速度更快（最高 fPCLK/8）但精度略低，CubeMX 默认 16 倍。

### 3.4 中断控制

**表 3-2 USART 中断请求一览**

| 中断事件 | 标志 | 使能位 | 典型用途 |
| --- | --- | --- | --- |
| 接收非空 | RXNE | RXNEIE | 中断方式收单字节 |
| 发送寄存器空 | TXE | TXEIE | 中断方式逐字节发送 |
| 发送完成 | TC | TCIE | DMA 发送、半双工方向切换 |
| 空闲线路 | IDLE | IDLEIE | 判定变长数据帧接收结束 |
| 校验错误 | PE | PEIE | 奇偶校验出错处理 |
| 溢出错误 | ORE | （随 RXNEIE） | 接收丢数报警 |

CubeMX 里在 NVIC 页勾选 **USART1 global interrupt**，生成的 `stm32f4xx_it.c` 会自动挂好 `USART1_IRQHandler → HAL_UART_IRQHandler()` 的骨架，用户只需重写回调函数，不需要像标准外设库那样手写中断服务程序里的寄存器操作。

## 4. HAL 库串口句柄与初始化参数

HAL 库用一个句柄结构体统管串口所有配置：协议参数放在 `Init` 子结构（类型 `UART_InitTypeDef`）， CubeMX 会替我们填好并生成初始化函数，理解每个成员含义即可。

```c
typedef struct {
  uint32_t BaudRate;                  // 波特率
  uint32_t WordLength;                // 字长：8B / 9B
  uint32_t StopBits;                  // 停止位：0.5/1/1.5/2
  uint32_t Parity;                    // 校验：NONE / EVEN / ODD
  uint32_t Mode;                      // 模式：TX / RX / TX_RX
  uint32_t HwFlowCtl;                 // 硬件流控：NONE / RTS / CTS / RTS_CTS
  uint32_t OverSampling;              // 过采样：8 倍 / 16 倍
} UART_InitTypeDef;
```

成员与 CubeMX 配置项对照：

**表 4-1 CubeMX Parameter Settings ↔ HAL 结构体成员**

| CubeMX 配置项            | 结构体成员          | 本笔记取值                  |
| --------------------- | -------------- | ---------------------- |
| Baud Rate             | `BaudRate`     | 115200                 |
| Word Length           | `WordLength`   | `UART_WORDLENGTH_8B`   |
| Stop Bits             | `StopBits`     | `UART_STOPBITS_1`      |
| Parity                | `Parity`       | `UART_PARITY_NONE`     |
| Mode                  | `Mode`         | `UART_MODE_TX_RX`      |
| Hardware Flow Control | `HwFlowCtl`    | `UART_HWCONTROL_NONE`  |
| OverSampling          | `OverSampling` | `UART_OVERSAMPLING_16` |

而引脚、时钟、中断这些**与具体 MCU 硬件绑定**的配置，由 `HAL_UART_MspInit()` 完成（HAL 弱函数，CubeMX 自动重写在 `stm32f4xx_hal_msp.c`），这是 HAL 库"协议抽象"与"硬件抽象"分层的精髓：换引脚、换串口只需重新生成 CubeMX 工程，应用层协议参数不动。

常用收发 API 一览：

**表 4-2 HAL 串口收发 API**

| API | 方式 | 说明 |
| --- | --- | --- |
| `HAL_UART_Transmit()` | 阻塞 | 轮询等 TXE/TC，超时退出；适合少量调试输出 |
| `HAL_UART_Receive()` | 阻塞 | 死等收到指定长度；单字节回显可用 |
| `HAL_UART_Transmit_IT()` | 中断 | 启动后靠 `HAL_UART_IRQHandler` 逐字节搬运，完成触发 `TxHalfCplt/TxCpltCallback` |
| `HAL_UART_Receive_IT()` | 中断 | 收满指定长度触发 `HAL_UART_RxCpltCallback`，**回调里必须重新使能** |
| `HAL_UART_Transmit_DMA()` 等 | DMA | 高速/长数据，完成触发对应 DMA 回调 |
| `HAL_UARTEx_ReceiveToIdle_DMA()` | DMA+空闲 | 不定长帧接收首选，IDLE 或半满即回调 |

## 5. STM32CubeMX 配置工程

以下以一个全新工程演示从零配置 USART1 的完整步骤。

### 5.1 新建工程与芯片选择

1. CubeMX 欢迎页 → **New Project**，在 *Select MCU* 搜索框输入 `STM32F407VET6`，选中 LQFP100 封装，确认进入工程。
![](Pasted%20image%2020261007111544.png)

### 5.2 系统时钟（RCC + Clock Configuration）

1. **RCC** → HSE 选择 **Crystal/Ceramic Resonator**（外部 8MHz 晶振）。
![](Pasted%20image%2020261007111633.png)
2. **Clock Configuration**：PLL 源选 HSE，PLL_M=8、PLL_N=336、PLL_P=2，系统时钟 **SYSCLK = 168MHz**；APB2 分频 ÷2 → **84MHz**（USART1/6 时钟），APB1 分频 ÷4 → **42MHz**（USART2/3、UART4/5 时钟）。
![](Pasted%20image%2020261007111740.png)
3. 若外部晶振不是 8MHz，按板子实际晶振调整 PLL_M。

### 5.3 配置 USART1

1. 左侧 **Connectivity → USART1**，Mode 选 **Asynchronous**。
2. 芯片图上出现 PA9（TX）/ PA10（RX），被自动配置为 AF7 复用。
3. **Parameter Settings**：按表 4-1 填 115200、8-N-1、TX+RX、无流控、16 倍过采样。
![](Pasted%20image%2020261007112407.png)
4. **NVIC Settings**：勾选 **USART1 global interrupt**（做中断接收实验必需；纯轮询打印可不勾）。
![](Pasted%20image%2020261007112432.png)
5. 若要用串口 2/6 等同理，注意 USART2 默认 PA2/PA3，USART6 在 VET6 上只能用 PC6/PC7。

### 5.4 工程生成设置

1. **Project Manager → Project**：填工程名、选择工程存放位置，工具链选 **MDK-ARM (V5)** 或 STM32CubeIDE。
![](Pasted%20image%2020261007112648.png)
2. **Project Manager → Advanced Settings** 建议勾选 *Generate separate peripheral init files*（`mx_peripheral.c/h`），方便把 `HAL_UART_MspInit` 相关改动与自己的代码隔离，重新生成工程不丢失。
3. 右上角 **GENERATE CODE**。
![](Pasted%20image%2020261007112754.png)

生成后重点关注三处代码：

- `usart.c`：`MX_USART1_UART_Init()` —— 协议参数初始化；
- `stm32f4xx_hal_msp.c`：`HAL_UART_MspInit()` —— 时钟/GPIO/NVIC 配置；
- `stm32f4xx_it.c`：`USART1_IRQHandler()` —— 中断入口（已自动生成，勿改）。

`HAL_UART_MspInit()` 生成结果参考（CubeMX 自动写入 `stm32f4xx_hal_msp.c`）：

列表 1: 代码清单 5-1 CubeMX 生成的 MspInit 关键片段

```c
void HAL_UART_MspInit(UART_HandleTypeDef* uartHandle)
{
  GPIO_InitTypeDef GPIO_InitStruct = {0};

  if (uartHandle->Instance == USART1)
  {
    /* 1. 使能 USART1 与 GPIOA 时钟 */
    __HAL_RCC_USART1_CLK_ENABLE();
    __HAL_RCC_GPIOA_CLK_ENABLE();

    /* USART1 GPIO Configuration
       PA9 ------> USART1_TX
       PA10 ------> USART1_RX */
    GPIO_InitStruct.Pin       = GPIO_PIN_9 | GPIO_PIN_10;
    GPIO_InitStruct.Mode      = GPIO_MODE_AF_PP;      /* 复用推挽 */
    GPIO_InitStruct.Pull      = GPIO_NOPULL;
    GPIO_InitStruct.Speed     = GPIO_SPEED_FREQ_LOW;
    GPIO_InitStruct.Alternate = GPIO_AF7_USART1;      /* 复用映射到 USART1 */
    HAL_GPIO_Init(GPIOA, &GPIO_InitStruct);

    /* 2. USART1 中断优先级配置（勾选 NVIC 后生成） */
    HAL_NVIC_SetPriority(USART1_IRQn, 0, 0);
    HAL_NVIC_EnableIRQ(USART1_IRQn);
  }
}
```

> **注意**：重新 GENERATE CODE 只会覆盖 `MX_..._Init` 等 CubeMX 管理区域，用户代码写在 `USER CODE BEGIN/END` 注释块内即不会被冲掉——这是 CubeMX 工程最重要的编码纪律。

## 6. 实验一：USART1 轮询收发回显

**实验目标**：开发板上电后通过 USART1 向电脑发送一串欢迎信息；在串口调试助手发送任意字符，开发板收到后原样回传（回显）。全程使用阻塞轮询，帮助理解"发—等 TC—读—清 RXNE"的基本时序。

### 6.1 硬件设计

板载 USB 转串口芯片（CH340/CP2102 等）的 TXD 接 PA10（USART1_RX），RXD 接 PA9（USART1_TX），GND 共地；用 USB 线连接开发板与电脑后，电脑端出现一个 COM 口。若使用外接 USB 转 TTL 模块，接线原则同样是 **交叉连 TX/RX、必须共地**。

### 6.2 软件设计

#### 6.2.1 编程要点

1. CubeMX 完成 USART1 异步模式、115200 8-N-1 配置并生成代码（时钟、GPIO 复用已由 MspInit 完成）；
2. 上电后调用 `HAL_UART_Transmit()` 发送欢迎字符串；
3. 主循环轮询 `__HAL_UART_GET_FLAG()` 判断 RXNE，收到数据后读走并回发；
4. 注意读取 DR 会软件清除 RXNE；ORE 置位时需先清 ORE 再清 RXNE，否则接收卡死。

#### 6.2.2 代码分析

列表 2: 代码清单 6-1 轮询回显（写入 main.c 的 while 循环）

```c
/* CubeMX 生成的 main.c 中，USER CODE 块内添加 */
uint8_t rx_byte = 0;

int main(void)
{
  HAL_Init();
  SystemClock_Config();          /* 168MHz */
  MX_GPIO_Init();
  MX_USART1_UART_Init();         /* 115200 8-N-1 */

  /* 上电发送欢迎语 */
  HAL_UART_Transmit(&huart1, (uint8_t *)"Hello, STM32F407VET6 UART!\r\n",
                    30, HAL_MAX_DELAY);

  while (1)
  {
    /* 轮询接收：阻塞等待 1 字节，100ms 超时 */
    if (HAL_UART_Receive(&huart1, &rx_byte, 1, 100) == HAL_OK)
    {
      /* 回显给电脑 */
      HAL_UART_Transmit(&huart1, &rx_byte, 1, 100);
    }
  }
}
```

分析：`HAL_UART_Receive()` 内部即"等待 RXNE → 读 DR"的轮询封装，读操作自动清除 RXNE；`HAL_UART_Transmit()` 内部逐字节等 TXE 写入、最后一字节等 TC。阻塞方式实现简单，但 CPU 全程等待，实际项目里回显这类需求一般改用中断（见实验二）。

#### 6.2.3 下载验证

编译下载到开发板，打开串口调试助手（选对应 COM 口、115200、8-N-1），接收区看到欢迎语；发送区输入任意字符点发送，接收区立刻出现相同字符，说明收发均正常。

## 7. 实验二：中断接收 + printf 重定向

**实验目标**：让开发板成为"C 语言控制台"——用 `printf` 直接向串口打印调试信息；用中断接收电脑指令，收到 `1` 亮 LED、收到 `0` 灭 LED，非法指令打印提示。这是日常调试中最实用的串口用法。

### 7.1 硬件设计

串口部分同实验一；LED 接一个普通 GPIO 输出（如 PB12 低电平点亮，以实际板子为准）。CubeMX 中为 PB12 配置 GPIO_Output，并重新生成代码。

### 7.2 软件设计

#### 7.2.1 编程要点

1. CubeMX 勾选 USART1 全局中断（已在工程配置时完成）；
2. 上电调用 `HAL_UART_Receive_IT()` 挂起单字节中断接收；
3. 重写弱回调 `HAL_UART_RxCpltCallback()`：处理收到的字节，并**再次调用 `HAL_UART_Receive_IT()`** 续挂下一次接收；
4. 重定向 C 库输出到串口（Keil 实现 `fputc` 并勾选 MicroLIB；GCC 实现 `_write`）；
5. 主循环根据标志位处理指令，中断里只做最短的事。

#### 7.2.2 代码分析

列表 3: 代码清单 7-1 中断接收框架（main.c 的 USER CODE 区）

```c
uint8_t rx_byte;
volatile uint8_t rx_flag = 0;   /* 收到一帧标志 */

int main(void)
{
  HAL_Init();
  SystemClock_Config();
  MX_GPIO_Init();
  MX_USART1_UART_Init();

  HAL_GPIO_WritePin(LED_GPIO_PORT, LED_PIN, GPIO_PIN_SET);
  printf("\r\n===== F407VET6 串口指令实验 =====\r\n");
  printf("发送 '1' 点亮 LED，发送 '0' 熄灭 LED\r\n");

  /* 挂起第一次中断接收：收到 1 字节即进中断 */
  HAL_UART_Receive_IT(&huart1, &rx_byte, 1);

  while (1)
  {
    if (rx_flag)
    {
      rx_flag = 0;
      switch (rx_byte)
      {
        case '1': HAL_GPIO_WritePin(LED_GPIO_PORT, LED_PIN, GPIO_PIN_RESET);
                  printf("LED ON\r\n");  break;
        case '0': HAL_GPIO_WritePin(LED_GPIO_PORT, LED_PIN, GPIO_PIN_SET);
                  printf("LED OFF\r\n"); break;
        default:  printf("未知指令: %c\r\n", rx_byte); break;
      }
    }
  }
}

/* 重写 HAL 弱回调：每收满 1 字节被 HAL_UART_IRQHandler 调用 */
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
  if (huart->Instance == USART1)
  {
    rx_flag = 1;
    /* 必须重新挂起，否则只收一次 */
    HAL_UART_Receive_IT(&huart1, &rx_byte, 1);
  }
}
```

列表 4: 代码清单 7-2 printf 重定向

**Keil MDK（需勾选 Options → Target → Use MicroLIB）：**

```c
/* 在任意 .c 文件（建议 main.c 或新建 bsp_printf.c），USER CODE 区添加 */
#if defined(__CC_ARM) || defined(__ARMCC_VERSION)   /* ARMCC/AC6 均适用 */
#pragma push
#pragma micro_lib
/* 重定向 fputc：printf 每输出一字符调用一次 */
int fputc(int ch, FILE *f)
{
  HAL_UART_Transmit(&huart1, (uint8_t *)&ch, 1, HAL_MAX_DELAY);
  return ch;
}
#pragma pop
#endif
```

**STM32CubeIDE（GCC/newlib）：**

```c
/* USER CODE BEGIN 0 */
#include <sys/stat.h>

/* 重定向 stdout：write 系统调用落到串口 */
ssize_t _write(int fd, const void *pdata, size_t bytes)
{
  HAL_UART_Transmit(&huart1, (uint8_t *)pdata, bytes, HAL_MAX_DELAY);
  return bytes;
}
/* 使用 printf 前先关闭缓冲，或输出后 fflush(stdout) */
/* USER CODE END 0 */
```

分析：

- `USART1_IRQHandler → HAL_UART_IRQHandler()` 由 CubeMX 生成在 `stm32f4xx_it.c`，它在 RXNE 中断里把 DR 数据搬进我们的 `rx_byte` 缓冲区，收满设定长度即调用弱回调 `HAL_UART_RxCpltCallback`，用户**只写回调、不写寄存器**。
- 单字节接收模式必须"回调里重新使能"，这是 HAL 中断接收最常见的坑；接收完成前若再来第二个字节会触发 ORE 溢出。
- `fputc`/`_write` 本质都是把 C 标准库的字符输出出口改接到 `HAL_UART_Transmit`，之后 `printf`、`putchar` 都能直接用。Keil 不勾 MicroLIB 时 `fputc` 重定向不生效；GCC 下 printf 默认行缓冲，建议加 `setvbuf(stdout, NULL, _IONBF, 0);`。

## 8. 扩展：DMA 不定长帧接收（思路）

定长中断接收每字节进一次中断，长数据流效率低。工程上接收"长度不定"的指令帧，推荐 **DMA + 空闲中断（IDLE）**：

1. CubeMX 为 USART1 增加 RX DMA Stream（Channel 4），DMA 模式 Circular、传输宽度 Byte；
2. 调用 `HAL_UARTEx_ReceiveToIdle_DMA(&huart1, rx_buf, sizeof(rx_buf));`，并执行 `__HAL_DMA_DISABLE_IT(&hdma_usart1_rx, DMA_IT_HT);` 关闭半传输中断（否则每半满都回调一次）;
3. 重写 `HAL_UARTEx_RxEventCallback(huart, size)`：回调触发时刻即"数据流出现空闲"，`size` 就是这一帧实际长度，处理完重新调用第 2 步的函数即可。

DMA 具体原理见《DMA—直接存储区访问》章节。

## 9. 本章小结

1. 串口分物理层（TTL/RS-232 电平、TX/RX/GND 三线交叉共地）和协议层（波特率、起始位、数据位、校验位、停止位，即"8-N-1"这类约定，双方必须一致）。
2. F407VET6 有 USART1/2/3/6 + UART4/5 共 6 个串口，APB2 组时钟 84MHz、APB1 组 42MHz；选引脚查表 2-1，注意 AF 编号与封装可用端口。
3. 内部结构核心：DR（TDR/RDR）、SR 标志位（TXE/TC/RXNE/ORE/IDLE）、BRR 小数分频。波特率手算理解误差来源即可，HAL 自动配置。
4. HAL 分层：协议参数在 `UART_InitTypeDef`（CubeMX 面板直填），引脚/时钟/中断在 `HAL_UART_MspInit`（CubeMX 自动生成），应用只需调 API + 写回调。
5. 三种收发姿势：阻塞（调试打印）、单字节中断（指令交互，记得回调里重新挂收）、DMA+IDLE（不定长高速数据流）。
6. printf 重定向：Keil = MicroLIB + `fputc`；GCC = `_write` + 关缓冲。

## 10. 常见问题速查

| 现象 | 最可能原因 | 处理 |
| --- | --- | --- |
| 乱码 | 双方波特率/校验/停止位不一致；系统时钟配置与实际晶振不符 | 核对 8-N-1 与波特率；确认 PLL 参数按实际 HSE 频率设置 |
| 完全收不到/发不出 | TX/RX 没交叉；没共地；引脚 AF 被占用或时钟没开 | 对照表 1-2 接线；查 CubeMX 引脚冲突 |
| 只能收一次 | 中断回调里忘记重新 `HAL_UART_Receive_IT()` | 在 `RxCpltCallback` 末尾重新挂接收 |
| 偶发丢字节（ORE） | 主循环处理太慢，下一个字节已到 | 缩短中断内工作；改用 DMA+IDLE |
| Keil printf 无输出 | 没勾 Use MicroLIB | Options → Target 勾选后重编译 |
| 重新生成代码后配置丢失 | 用户代码写在 CubeMX 管理区 | 所有手写代码放进 `USER CODE BEGIN/END` 块 |
