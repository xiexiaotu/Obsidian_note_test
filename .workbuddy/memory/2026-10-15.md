2. `LCD_ShowChar()` / `LCD_ShowString()` 未声明未实现（第 7 章却在调用）→ 补齐声明与完整实现（8×16 点阵 `asc2_1608[95][16]` 取模、按字符开窗写 128 像素）；

4. DMA 段"渲染代码略" → 补齐 `LCD_RenderString()` 完整实现；补 `lcd_dma.h`。

已修复的逻辑错误（关键）：
- **M2M 的 PeriphInc/MemInc 语义写反**：F4 HAL 中源地址进 PAR（受 PeriphInc 控制）、目的进 M0AR（受 MemInc 控制），故必须 `PeriphInc = ENABLE`（帧缓冲自增）、`MemInc = DISABLE`（LCD 数据口固定）。已加"语义陷阱"提示框并写入速查表；
- **回调机制错误**：F4 HAL 无 `HAL_DMA_XferCpltCallback()` 可覆盖，须把 `XferCpltCallback`/`XferErrorCallback` 挂到句柄上，且必须在 `HAL_DMA_Init()` 之后（Init 会清空回调指针）；
- 出错回调未清 `dma_busy` → 一次错误永久锁死接口；启动失败也未解锁；均已在代码中处理；
- DMA 传输个数用原始 w*h 而 `LCD_OpenWindow` 会裁剪窗口 → 越界写入，已在 `LCD_DMA_FillBuffer` 加边界拒绝；
- `LCD_RefreshRow` 注释称"先盖背景"但未实现 → 真加 `LCD_Fill` 清背景；标题行会被数据刷新覆盖 → 标题独占 y=8、数据行移到 y=48 起；
- 采集耗时 200ms → 修正为 ≈70ms（HTU21D No-Hold 50+16ms 是 `HAL_Delay` 空转；BH1750 连续模式无需等待）；据此重写 CPU 占用表与"DMA 收益有限、价值在于把搬运藏进 I2C 等待窗口"的结论；
- 行宽参数从 300/LCD_WIDTH-16 不一致 → 统一 `ROW_W 320`；补充 LIS3DH_Init/PCF8563_IsTimeValid 的结果显示；
- 新增速查表条目：DMA 花屏（自增配反）、刷一次不动（回调未解锁）、`DMA2_Stream0_IRQHandler` 重复定义、与《ADC 采集配置》ADC1 抢 DMA2 Stream0；
- 第 5.2 节补充了当时用户问过的 CubeMX "Partly disabled conflict … NE1 Chip Select" 警告的含义与核对方法。

## 追加：回应"LIS3DH_Init / PCF8563_IsTimeValid 是否也缺声明定义"

核对结论：**这两个函数不缺**——它们属于《IIC 通信》笔记第 9 章器件层，声明在 `bsp_lis3dh.h`（`uint8_t LIS3DH_Init(void)`、`void LIS3DH_ReadAcc(short*)`）与 `bsp_pcf8563.h`（`uint8_t PCF8563_IsTimeValid(void)`，1=可信/0=掉电），实现分别在对应 .c 中，完整存在。
为消除歧义，笔记第 7 章做了两处增强：
1. 表 7-1 增加"头文件"列并写全原型与返回值语义；表后加提示块，明确"这些函数不在本笔记定义、不必重写，只需 include 头文件；移植时把 6 个 IIC 驱动文件 + bsp_lcd + lcd_dma 一起加入工程"；
